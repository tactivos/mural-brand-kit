Pattern library

Pattern library pages for review, refinement, and approval.

This first-pass library turns the written kit into fixed-page visual patterns. Each page is a draft review surface, not a final approved template. The goal is to evaluate hierarchy, spacing, and pattern usefulness before promoting any module into the recommended set.

Editorial Comparison Access matrix Stat / proof Image / screenshot Supporting

Review these patterns one by one. Adjust brand tone, spacing, hierarchy, and usage rules here before they become normalized building blocks for the generator kit.

Starter role

A minimal file for new PDFs. It should stay generic, stable, and easy to duplicate.

Pattern-library role

A draft catalog of optional modules. It should be explicit, reviewable, and visually labeled.

Example role

A finished subject-matter piece that demonstrates how approved patterns work in a real document.

Approval mindset

Treat every pattern as provisional until it is tuned for brand and added to the recommended pattern set.

Image-led patterns

Support both one-up and two-up image layouts. Screenshots, ecosystems, diagrams, and logo matrices should function as editorial content blocks, not as filler.

Pattern: Single placed image, full width

Typical pairings: narrative copy above, bullets below, or a partner / certification strip at the bottom of the section.

Single ecosystem graphic Use when one placed visual communicates a complete idea more clearly than breaking the information into smaller modules.

Pattern: Single placed image, 3/4 width

Use when the image should align more closely to the text-column width above it instead of spanning the full available content width.

Contained placed image Use when the image should feel editorially tied to the column measure above rather than reading as a full-width panel.

Pattern: Two-up image layout

This works well when the visual story benefits from sequence, comparison, or paired proof objects.

Image A Workflow step, screenshot, or concept visual.
Image B Second step, companion visual, or comparison state.

Pattern: Annotated screenshot

Product screenshot Annotated only when callouts materially improve understanding.
Callout one: identify the key action or UI step.
Callout two: explain why the screenshot matters to the story.
Callout three: keep annotations concise and editorial.
